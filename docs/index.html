Overview

Minima-PiNet-OS (v3.0.0) is a zero-bloat, blockchain-native operating system that turns an $80 Raspberry Pi into a self-sovereign edge cloud.

Minima L1 Blockchain

Full node in <500 MB. UTXO model, MMR proof database, KISSVM scripting, WOTS+ post-quantum signatures. Every user is a complete node.

CPIP Security Provider

AES-256-GCM, ECDSA P-256, Hybrid ECDH + Kyber ML-KEM-768, HMAC-SHA256 RPC auth, ITF Defense probe blocking.

k3s Edge Cluster

Lightweight Kubernetes for containerised workloads. LXC with cgroups v2 quotas, up to 16 tenants per node.

On-Device AI

Hailo-8L NPU (13 TOPS) for local LLM inference via Ollama/GGUF. ARM NEON fallback on Pi 4.

Browser Desktop

FastAPI + Jinja2 web UI with 23+ built-in apps: terminal, system monitor, cluster manager, wallet, AI assistant.

Confidential Computing

Arm CCA / RISC-V AP-TEE enclaves, zkVM verifiable compute proofs, decentralized edge compute marketplace.

Quick Start: Flash & Boot (Raspberry Pi)

1

Download the Image

Download PiNetOS-RaspberryPi.img from the latest release.

2

Verify Integrity

sha256sum --check SHA256SUMS.txt
3

Flash the Image

Use Raspberry Pi Imager (recommended):

  1. Click CHOOSE OS → Use custom → select PiNetOS-RaspberryPi.img
  2. Click CHOOSE STORAGE → select your SD card or NVMe
  3. (Optional) Click the gear icon to pre-configure Wi-Fi, hostname, and SSH
  4. Click WRITE

Or use dd:

sudo dd if=PiNetOS-RaspberryPi.img of=/dev/sdX bs=4M status=progress conv=sync,noerror
sync
4

First Boot

  1. Insert the flashed storage into your Raspberry Pi and power on
  2. First-boot provisioning takes ~2 minutes
  3. Access the dashboard at http://<pi-ip>:3000
Default credentials: username pinet, password pinet — change immediately with passwd.

Quick Start: Spawnable Runtime (Any Linux)

PiNet-OS runs as a contained environment on any existing Linux distro on Raspberry Pi. No dedicated image flashing required.

# 1. Clone the repository
git clone https://github.com/WilliamMajanja/Minima-PiNet-Os.git
cd Minima-PiNet-Os

# 2. Run the setup script (installs Java, Python, downloads Minima)
bin/pinet setup

# 3. Start PiNet-OS
bin/pinet start --role master    # For the first node (master)
# OR
bin/pinet start --role worker --master <address>  # For worker nodes

What Setup Does

  1. Checks and installs Java 17+ (for the Minima node)
  2. Checks and installs Python 3.11+ (for the FastAPI/Jinja web desktop)
  3. Downloads the Minima JAR to ~/.pinet/bin/minima.jar
  4. Installs the Python desktop's requirements.txt
  5. Generates node identity and initial configuration

Managing the Runtime

pinet status             # Show runtime status
pinet stop               # Stop all services
pinet logs --follow      # Tail service logs
pinet shell              # Attach to PiNet-OS session
pinet cluster            # Show cluster topology
pinet open               # List available apps
pinet detect             # Detect Pi model and hardware
pinet config show        # View configuration

Quick Start: Local Desktop Demo

Run the full web desktop UI locally in under two minutes — no Raspberry Pi required.

# 1. Clone and enter the repo
git clone https://github.com/WilliamMajanja/Minima-PiNet-Os.git
cd Minima-PiNet-Os

# 2. Install Python dependencies
pip install -r requirements.txt

# 3. Copy and configure environment
cp .env.example .env

# 4. Start the desktop server
python run.py

Open http://localhost:3000 — you get the full desktop, system monitor, terminal, and cluster manager.

Minima Blockchain Node

Minima is a decentralized L1 blockchain with a UTXO model, MMR proof database, covenants, MAST, and post-quantum signatures (WOTS+). Every user runs a full node.

Running Minima Standalone

# Download the latest Minima JAR
wget -O minima.jar https://github.com/WilliamMajanja/minima-core/releases/latest/download/minima.jar

# Start with default parameters (connects to mainnet)
java -jar minima.jar

# With MDS (MiniDAPP System) enabled
java -jar minima.jar -mdsenable -mdspassword YOUR_PASSWORD -port 9001

# Private test-net
java -jar minima.jar -nop2p -test -genesis

Minima Core Security

The Minima Core codebase has undergone a comprehensive security audit with 80 CodeQL alerts remediated across 7 categories (SSRF, path traversal, SQL injection, RSA-OAEP, RSA key size, AES-CBC, static IV). All 278 tests pass. Verified on mainnet (v1.0.46.8, block 2,219,786+).

Forming a PiNet Cluster

PiNet-OS clusters use the Maxima protocol (Minima's encrypted P2P bus) for all coordination. No central API server, no shared database.

1

Start the Master Node

pinet start --role master

This starts: Minima node (P2P :9001, RPC :9005), cluster manager (API :9090), web desktop (:3000), initializes cluster state, begins broadcasting heartbeats.

2

Join Worker Nodes

pinet start --role worker --master <master_maxima_address>
# OR
pinet join <master_maxima_address>
3

Verify the Cluster

pinet cluster

Or open the browser desktop at http://<any-node-ip>:3000 and navigate to the Cluster Manager app.

Cluster Protocol

CLUSTER_JOIN_ACCEPTMaster → WorkerAcceptance + peer list
CLUSTER_HEARTBEATAll → MasterLiveness + metrics (every 10s)
CLUSTER_STATE_UPDATEMaster → AllTopology changes
CLUSTER_EXEC_REQUESTMaster → WorkerRun a workload
CLUSTER_EXEC_RESULTWorker → MasterWorkload result
NODE_DEREGISTERAny → MasterGraceful departure

Node Health

  • Active: Heartbeat received within 30 seconds
  • Stale: No heartbeat for 30–60 seconds
  • Offline: No heartbeat for >60 seconds

CPIP Security Provider

The Coffee Protocol (CPIP) v5.0.0 is the primary security provider for all Minima nodes. Enabled by default (CPIP_ENABLED=1).

CoffeeCipher v3

AES-256-GCM (FIPS 197) with 12-byte nonce and 16-byte authentication tag. Key derivation via HKDF-SHA256 with domain-separated info strings. Format: nonce(12B) || ciphertext || GCM-tag(16B).

HybridKEM (Classical + Post-Quantum)

ECDH P-256 + 1nf1D3L Kyber, combined via HKDF-SHA256. Secure if EITHER classical ECDH OR PQ Kyber component holds. PK~1251B, SK~2432B, CT~1187B, SS=32B.

ITF Defense

  • Probe blocking: Returns HTTP 418 "I'm a teapot" to known scanning tools
  • Pentest tool fingerprinting: Detects 16 security tools (Burp Suite, Nmap, SQLMap, Nikto, etc.)
  • IP blacklisting: Rate-limited exponential ban duration (base 1 hour, up to 24 hours)
  • Stealth mode: Togglable at runtime via API
  • Defense policy groups: Anti-ISP, Anti-Stingray, Anti-Surveillance, Net-Neutrality — all independently togglable at runtime

Architecture Overview

Two-Layer Design

Layer 1: PiNet-OS Runtime (Linux)

  • CLI launcher (bin/pinet) — single POSIX shell script
  • Minima node — blockchain identity, trust, Maxima P2P bus
  • Go cluster manager — heartbeats, health, workloads, metrics
  • Systemd services for production deployment

Layer 2: Browser Desktop (Python)

  • FastAPI backend — API server, WebSocket terminal
  • Jinja2 desktop UI — 23+ built-in apps
  • Real-time updates via WebSocket channels

Trust Model

PiNet-OS implements a zero-trust, locally-anchored trust model:

  • Identity: ECDSA P-256 keypair via CPIP. Public key registered as Minima address. All Maxima P2P messages signed and encrypted.
  • Attestation: TPM 2.0 PCR values hashed and recorded on Minima blockchain. Tamper detectable.
  • Key Management: CPIP master keys PCR-sealed to TPM. Unseal only on matching boot path.
  • Network: All cluster traffic via encrypted WireGuard tunnels. Kubernetes NetworkPolicy default-deny.
